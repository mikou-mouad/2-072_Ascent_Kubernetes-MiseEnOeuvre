Chapitre 5 · Le concept

Labels, annotations, sélecteurs

metadata:
  labels:                         # pour sélectionner
    app.kubernetes.io/name: back
    app.kubernetes.io/part-of: festipass
    app.kubernetes.io/version: "1.0"
    app.kubernetes.io/component: api
    environnement: prod
  annotations:                    # pour informer
    festipass.example/equipe: billetterie
    kubernetes.io/change-cause: "back 1.0"

kubectl get pods -l app.kubernetes.io/part-of=festipass
kubectl get pods -l 'environnement in (prod,recette)'
kubectl get pods -l 'environnement!=prod'
kubectl get pods -L app.kubernetes.io/version
kubectl get pods --show-labels

Égalité ou ensemble

=, != · in, notin, ou juste la clé : -l environnement

Le sélecteur d'un Deployment est immuable

Choisissez vos labels avant le premier apply.

Labels : courts, pour sélectionner (Services, Deployments, kubectl -l, NetworkPolicies). Annotations : pour informer des outils ou des humains, jamais pour sélectionner. Les labels app.kubernetes.io/* sont la convention recommandée, reconnue par de nombreux outils. Changer le selector d'un Deployment est refusé : il faut le supprimer et le recréer. Au TP, on retire un label à un pod pour le sortir de son Service (quarantaine) et l'examiner.
