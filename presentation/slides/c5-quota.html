Chapitre 5 · Le concept

Des garde-fous par namespace

LimitRange : par conteneur, défauts et maximum

apiVersion: v1
kind: LimitRange
metadata:
  name: defauts
  namespace: recette
spec:
  limits:
  - type: Container
    defaultRequest: {cpu: 100m, memory: 128Mi}
    default:        {cpu: 500m, memory: 256Mi}
    max:            {cpu: "1",  memory: 512Mi}

ResourceQuota : un total pour tout le namespace

apiVersion: v1
kind: ResourceQuota
metadata:
  name: plafond
  namespace: recette
spec:
  hard:
    requests.cpu: "2"
    requests.memory: 2Gi
    limits.memory: 4Gi
    pods: "10"

Au-delà du quota, la création est refusée. Le LimitRange complète les pods qui n'ont rien déclaré.

Avec un ResourceQuota sur la mémoire, tout pod du namespace doit déclarer requests et limits, sinon il est refusé : le LimitRange évite ce piège en posant des valeurs par défaut. Le refus apparaît dans les Events du ReplicaSet, pas du Deployment : faire chercher avec kubectl describe rs. kubectl describe quota -n recette montre la consommation.
