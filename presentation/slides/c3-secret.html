Chapitre 3 · Le concept

Un Secret est caché, pas chiffré

kubectl create secret generic festipass-db -n festipass \
  --from-literal=POSTGRES_PASSWORD=maree-haute-2026 \
  --dry-run=client -o yaml | kubectl apply -f -

kubectl get secret festipass-db -n festipass -o yaml
  POSTGRES_PASSWORD: bWFyZWUtaGF1dGUtMjAyNg==
echo bWFyZWUtaGF1dGUtMjAyNg== | base64 -d
maree-haute-2026

env:
- name: DB_PASSWORD
  valueFrom:
    secretKeyRef: {name: festipass-db, key: POSTGRES_PASSWORD}

base64 n'est pas du chiffrement

Qui peut lire le Secret lit le mot de passe.

RBAC

Limiter qui peut lire les Secrets (chapitre 9).

Chiffrement au repos

Chiffrer les Secrets dans etcd (EncryptionConfiguration).

Outils externes

Sealed Secrets, External Secrets, Vault.

Le Secret est généré par une commande, jamais écrit dans un fichier commité : on commite la commande, pas la valeur. Le mot de passe a changé, puisque l'ancien a fuité. Un Secret apporte quand même quelque chose : il est séparé de la ConfigMap, on peut en restreindre la lecture par RBAC, et le kubelet le monte en mémoire (tmpfs). Attention : PostgreSQL ne lit POSTGRES_PASSWORD qu'à l'initialisation d'une base vide.
