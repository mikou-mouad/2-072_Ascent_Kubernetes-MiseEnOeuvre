Chapitre 9 · Le concept

Ce qu'un pod a le droit de faire

spec:
  serviceAccountName: back
  automountServiceAccountToken: false  # pas besoin de l'API
  securityContext:
    runAsNonRoot: true
    seccompProfile: {type: RuntimeDefault}
  containers:
  - name: back
    securityContext:
      allowPrivilegeEscalation: false
      readOnlyRootFilesystem: true
      capabilities: {drop: [ALL]}

ServiceAccount

L'identité du pod face à l'API. Par défaut : default, avec un token monté dans le conteneur.

Pod Security Admission

privileged

baseline

restricted

Un niveau par namespace, posé par un label :

kubectl label ns festipass \
  pod-security.kubernetes.io/enforce=restricted

Le back n'appelle jamais l'API Kubernetes : inutile de lui monter un token. Les images de FestiPass sont déjà prêtes pour restricted : le back tourne en utilisateur 10001, le front avec nginx-unprivileged (utilisateur 101). privileged : aucune restriction ; baseline : bloque les dangers connus (privileged, hostPath, hostNetwork) ; restricted : impose le securityContext ci-contre. PostgreSQL demande un runAsUser explicite (999) et un fsGroup pour passer en restricted. Tester d'abord avec le mode warn au lieu de enforce.
